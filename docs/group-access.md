# 그룹 워크스페이스와 최소 인증

## 목적과 범위

신뢰하는 소규모 그룹이 일정·작업을 함께 관리한다. 개인 회원가입 없이 운영자 계정 하나와 그룹별 입장 코드를 사용한다. Project 하나가 워크스페이스 하나이며 기존 프로젝트·작업은 그대로 보존한다. 기존 프로젝트는 관리자가 코드를 발급하기 전까지 관리자만 접근할 수 있다.

## 권한

| 작업 | 참여자 | 관리자 |
|---|---|---|
| 현재 그룹의 작업 조회·생성·수정, 댓글·첨부 링크 추가 | 가능 | 가능 |
| 담당자 표시 이름·목록 추가·수정 | 가능 | 가능 |
| 담당자 삭제 | 불가 | 가능 |
| 작업 휴지통 이동 | 가능 | 가능 |
| 휴지통 복구·영구 삭제 | 불가 | 가능 |
| 그룹 생성·이름 변경·삭제·코드 재발급 | 불가 | 가능 |
| 선택한 그룹 백업 다운로드·저장·복원 | 불가 | 가능 |

담당자 이름과 역할 문구는 로그인 신원·접근 권한이 아니다. 개별 참여자 추적·차단은 지원하지 않는다. 코드 유출 시 재발급하면 해당 그룹의 참여자 세션이 모두 만료된다. 작업 삭제 시 하위 작업은 남기고 상위 연결을 해제한다. 복구한 작업은 독립 작업으로 돌아온다.

## 초기 설정

1. `node scripts/create-admin.cjs admin-credentials.local.json https://sprintflow.apps.swkoo.kr` 실행. 기존 파일은 덮어쓰지 않는다.
2. 생성 파일의 `environment` 항목 네 개를 서버 Secret/환경변수에 설정한다. `password`는 운영자가 보관하고 서버에 배포하지 않는다. 로컬 개발은 실제 접속 origin을 사용한다.
3. `/admin/login`에서 파일의 아이디·비밀번호로 로그인한다.
4. 그룹을 만들거나 기존 그룹에 입장 코드를 발급한다. 코드는 발급 직후 한 번만 표시되므로 필요한 참여자에게 안전하게 전달한다.
5. 참여자는 `/login`에서 코드로 입장한다. 관리자는 그룹 관리에서 워크스페이스를 선택한다.

생성 파일은 Git/Docker에서 제외되며 비밀번호가 포함되어 있으므로 안전하게 보관한다. `NEXT_PUBLIC_*` 변수나 GitHub 소스에 인증 값을 넣지 않는다. 설정 누락 시 접근을 허용하지 않는다. 로그인 쿠키는 24시간 만료, HttpOnly/SameSite=Strict, 운영에서는 Secure 및 __Host- 접두사를 사용한다. 운영 HTTPS가 필요하다.

## 운영과 제한

- 관리자 비밀번호 변경: 새 해시로 Secret을 갱신하고 앱을 재시작한다. 이전 관리자 세션은 무효화된다. `SESSION_SECRET` 변경은 모든 세션을 무효화한다.
- 관리자 비밀번호 분실: 서버 Secret을 변경할 수 있는 운영자가 재설정한다. 웹 비밀번호 재설정·이메일 발송은 제공하지 않는다.
- 로그인 시도 제한은 단일 인스턴스의 SQLite에 저장한다. 5분 구간마다 관리자 20회, 그룹 입장 60회로 전체 요청을 제한한다. 재시작으로 초기화되지 않지만 공격자가 한도를 소진하면 정상 입장도 다음 구간까지 지연될 수 있다. 대규모 공개 서비스용 계정 인증을 대체하지 않는다.
- 그룹 코드는 144비트 무작위 값이며 서버에는 SHA-256 해시만 저장한다. 관리자 비밀번호는 salt를 사용한 scrypt 해시로 저장한다.
- 모든 데이터 API는 서버 세션의 프로젝트 ID를 사용한다. 관계 ID도 같은 프로젝트 소속인지 확인한다. 변경 요청은 설정된 APP_ORIGIN과 Origin이 일치해야 한다.
- 첨부는 외부 URL 연결 기능이다. SprintFlow 내부의 첨부 목록은 격리하지만 외부 파일 자체의 권한은 파일 제공 서비스에서 관리한다.
- 백업은 선택한 그룹만 포함하고 코드 해시·세션·관리자 인증 정보를 제외한다. 복원은 같은 프로젝트 ID에만 가능하며 해당 그룹 참여자 세션을 만료한다. 다른 그룹은 보존된다.
- 기존 그룹 이전의 전체 DB 백업 파일은 여러 그룹이 포함되어 있으면 웹 복원에서 거부한다. 관리자 수동 검토가 필요하다. 기존 서버 백업은 삭제하지 않으며 새 백업은 프로젝트별 디렉터리에 저장한다. 자동 백업·외부 백업 인프라는 추가하지 않는다.

## 마이그레이션과 검증

운영은 `prisma migrate deploy`로 `001_group_access`를 적용한다. 기존 테이블을 재생성하지 않고 인증용 열, 휴지통 열, 로그인 제한 테이블을 추가한다. 로컬 `db:push` 스크립트도 같은 추가 변경을 반복 적용할 수 있다. 운영 DB에 `--reset`을 사용하지 않는다.

`npm test`는 비밀번호·서명·만료·기존 데이터 보존을 검사한다. `npm run build` 후 `npm run test:integration`은 별도 임시 SQLite와 실제 HTTP 서버에서 비로그인 차단, 그룹 간 조회/변경·관계 ID 공격, 관리자 권한, CSRF, 백업 격리, 코드 재발급과 세션 만료를 검증한다.
