## 2. 구분 예시

- 신규: 아직 없는 기능
- 개선: 기존 기능의 사용성 또는 정책 변경
- 버그: 의도와 다르게 동작하는 문제
- 문서: 기획/운영 문서 보강
- 기술부채: 구조 개선, 성능, 보안, 테스트

## 3. 우선순위 기준

- 긴급: 작업 진행을 막거나 데이터 손실 위험이 있음
- 높음: 주요 사용자 흐름에 직접 영향이 있음
- 보통: 사용성 개선 또는 반복 작업 감소
- 낮음: 있으면 좋지만 당장 운영에 영향이 적음

## 4. 상태 기준

- 제안: 아직 검토 전
- 검토 중: 범위와 방식 논의 중
- 확정: 구현 대상
- 진행 중: 개발 중
- 완료: 구현 및 검증 완료
- 보류: 당장 진행하지 않음
