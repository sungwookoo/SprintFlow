# SprintFlow 기능 정의서

## 1. 화면별 기능

### 대시보드

- 전체 상위 작업 수를 표시한다.
- 완료율을 표시한다.
- 활성 스프린트의 완료 포인트와 전체 포인트를 표시한다.
- 플래그 및 마감 임박 작업을 주의 항목으로 표시한다.
- 담당자별 미완료 작업 수와 story point를 표시한다.

### 보드

- 활성 스프린트의 상위 이슈를 상태 컬럼별로 표시한다.
- 이슈 카드는 타입, 우선순위, 담당자, 마감일, 진행률, 하위작업 완료 수를 표시한다.
- 이슈 카드를 드래그해 다른 상태 컬럼으로 이동할 수 있다.
- 이슈 카드를 클릭하면 상세 패널을 연다.

### 백로그

- 활성 스프린트, 계획 스프린트, 백로그 섹션으로 이슈를 나누어 표시한다.
- 빠른 작업 생성 폼을 제공한다.
- 이슈 상태와 스프린트를 행에서 바로 변경할 수 있다.
- 이슈를 클릭하면 상세 패널을 연다.

### 일정

- 현재 월 기준 캘린더를 표시한다.
- 마감일이 있는 상위 이슈를 날짜 칸에 표시한다.
- 이전 달, 다음 달 이동을 지원한다.
- 일정 항목 클릭 시 이슈 상세 패널을 연다.

### 이슈 목록

- 모든 이슈와 하위작업을 리스트로 표시한다.
- 상태를 직접 변경할 수 있다.
- 이슈 클릭 시 상세 패널을 연다.

### 이슈 상세 패널

- 제목, 설명, 라벨을 편집한다.
- 상태, 스프린트, 담당자, 우선순위, 플래그를 변경한다.
- 시작일, 마감일, story point, 예상 시간, 기록 시간을 편집한다.
- 하위작업을 추가하고 하위작업 상태를 변경한다.
- 댓글을 추가한다.
- 첨부 메타데이터를 추가한다.

### 설정

- 프로젝트 설정 요약을 표시한다.
- 서버 백업 저장, 최신 백업 복원, 파일 다운로드, 파일 복원을 제공한다.
- 담당자 사용자를 추가, 수정, 삭제한다.

## 2. 백업/복원 정의

### 서버 백업 저장

- 현재 SQLite DB의 주요 테이블을 JSON 스냅샷으로 export한다.
- 저장 위치는 `prisma/backups`이다.
- 파일명은 `sprintflow-backup-{ISO_TIMESTAMP}.json` 형식이다.
- 버튼 클릭 후 확인 패널에서 `저장 실행`을 눌러야 저장된다.

### 최신 백업 복원

- `prisma/backups`에서 가장 최근 JSON 백업을 찾는다.
- 현재 DB 데이터를 삭제하고 백업 데이터로 교체한다.
- 복원 대상은 프로젝트, 상태, 스프린트, 사용자, 이슈, 댓글, 첨부이다.

### 파일 다운로드

- 현재 DB 데이터를 JSON 백업 파일로 브라우저에 다운로드한다.
- 서버 백업 폴더에는 저장하지 않는다.

### 파일로 복원

- 사용자가 선택한 JSON 백업 파일을 읽어 현재 DB를 교체한다.
- 백업 포맷이 SprintFlow 스키마와 맞지 않으면 복원하지 않는다.

## 3. 데이터 모델 요약

### Project

- 프로젝트 키, 이름, 설명, 리드, 색상, 시작일, 목표일

### Status

- 프로젝트별 상태 이름, 카테고리, 색상, 정렬 순서

### Sprint

- 프로젝트별 스프린트 이름, 목표, 상태, 시작일, 종료일

### Member

- 프로젝트별 담당자 이름, 이니셜, 역할, 색상

### Issue

- 이슈 키, 타입, 제목, 설명, 우선순위, 라벨, 포인트, 추정/기록 시간, 상태, 담당자, 보고자, 스프린트, 부모 이슈, 일정

### Comment

- 이슈별 댓글 본문, 작성자, 작성일

### Attachment

- 이슈별 첨부 파일명, URL, 파일 크기, 등록일

## 4. API 요약

- `POST /api/issues`: 이슈 생성
- `PATCH /api/issues/[id]`: 이슈 수정
- `DELETE /api/issues/[id]`: 이슈 삭제
- `POST /api/issues/[id]/comments`: 댓글 생성
- `POST /api/issues/[id]/attachments`: 첨부 메타데이터 생성
- `POST /api/members`: 사용자 생성
- `PATCH /api/members/[id]`: 사용자 수정
- `DELETE /api/members/[id]`: 사용자 삭제
- `GET /api/backups/download`: 백업 파일 다운로드
- `GET /api/backups/save`: 서버 백업 목록 조회
- `POST /api/backups/save`: 서버 백업 저장
- `POST /api/backups/restore`: 최신 백업 또는 업로드 백업 복원

## 5. 제약과 주의사항

- 현재는 단일 사용자 로컬 앱이다.
- DB 파일과 백업 파일은 git에 포함하지 않는다.
- 첨부는 실제 파일 업로드가 아니라 메타데이터 저장이다.
- 사용자 삭제 시 담당/보고자 참조는 비워진다.
- 권한 기능이 없으므로 모든 설정과 데이터 변경이 즉시 가능하다.
